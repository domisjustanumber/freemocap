# GPU & ONNX Runtime Setup

FreeMoCap uses ONNX Runtime for GPU-accelerated pose detection via RTMPose. GPU acceleration significantly improves realtime pipeline throughput — especially with multiple cameras. The models, the execution providers (EPs) and their selection are implemented in [SkellyTracker](https://freemocap.github.io/skellytracker/guides/gpu-setup); FreeMoCap configures them through the pipeline.

## How GPU Detection Works

FreeMoCap does not detect GPUs or execution providers itself; SkellyTracker does. On startup, the Python backend (`freemocap/app/app.py`) logs what SkellyTracker reports:

- **Host**: OS, CPU, cores, memory and each GPU (name, vendor, VRAM, driver), from SkellyTracker's host probe
- **Execution providers**: each one SkellyTracker knows on this host with its state, and its recommendation for performance

The execution provider menu offers Auto (SkellyTracker's recommendation) and the providers SkellyTracker lists on this host, with SkellyTracker's description of each and, for one that is not usable yet, its install hint. Run `skellytracker-eps status` for the same report in a terminal.

## Execution Providers

Which EPs exist, what hardware and drivers each needs and how to install its pack are documented by [SkellyTracker](https://freemocap.github.io/skellytracker/guides/gpu-setup). FreeMoCap keeps no list of its own: the in-app menu and `skellytracker-eps status` show the EPs of this computer. CPU is always available.

## Configuration

### Realtime Pipeline

The EP is configured in the `RealtimeSkeletonInferenceNodeConfig`:

```python
RealtimeSkeletonInferenceNodeConfig(
    execution_provider=None,  # None is Auto, SkellyTracker's recommendation; otherwise a SkellyTracker EP key
    execution_device=None,    # a SkellyTracker device key of the chosen EP; None is SkellyTracker's choice
)
```

SkellyTracker refuses a key it does not have, or one that cannot start, when the run starts; FreeMoCap shows its message. A single `RealtimeSkeletonInferenceNode` handles skeleton detection for all cameras in one batched run. MediaPipe takes no EP.

### Post-hoc Processing

Post-hoc processing uses the same EP setting from the mocap settings; Auto takes SkellyTracker's recommendation, including its options and device.

## GPU Out of Memory

When a GPU runs out of memory during a call, SkellyTracker closes the run with an out-of-VRAM error. Start processing again with fewer cameras, a lower resolution, or another EP.

## Troubleshooting

**An EP is listed but not usable**
→ Follow the install hint shown under the EP menu (the same text as in `skellytracker-eps status`).

**"GPU OOM with many cameras"**
→ Reduce camera resolution or the number of cameras, or use a GPU with more VRAM.
